Connected stage syntax is reserved but execution is unavailable in this build. A connected stage has id, optional title, after and if, plus connect: {"to":"vectorscope","action":"review","input":{"target":{"kind":"branch","base":"main"}}}. Its inputs are literal review options; it cannot select an agent, model, prompt, background mode, helper scope or budget parent. Only an engine-owned member manifest with a nonempty list of read effects can validate the action. Workflow JSON cannot declare those effects. The production workflow planner currently supplies no connected manifest, so validation refuses these stages. The scheduler also refuses a connect-bearing workflow before any source, task or provider runs. Ordinary reviewer prompts do not yet preserve the private workflow, group and ancestor budget scopes; a separate dollar cap does not replace those scopes. Do not offer an implement/review/fix/review workflow as available until that private scope port is approved and qualified. Existing workflow approval and any required connect_model consent remain separate owner decisions.

The prepared connected output format keeps the actual review state and verdict and exposes findings as data items with their run ID and owned_paths. Ownership is the intersection of resolved findings and actual changed files, excluding protected paths. It never derives write authority from finding text, and a partial or refused review cannot imply clean. This projection does not activate connected workflow execution.
