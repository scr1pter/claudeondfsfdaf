General

Manage what Vector does while it works, diagnostics, verification defaults, and the terminal shell. Memory has a page of its own.

While Vector works

What a message you send, and Stop, do while Vector is working. These apply on this device only.

Follow-up behavior
Steer, the default, joins your message to the running turn at its next step. Queue holds it until the turn ends. Alt+Enter (Option+Enter on a Mac) does the other for one message; slash commands and shell input always queue.
Stop button
What Stop, Esc and Ctrl+G stop. Helpers are the subagents, workflow runs and background commands this conversation started; their partial work is kept, and agent workspaces keep running.

Crash diagnostics

Optional technical error reports. Disabled until you explicitly enable them.

Share crash diagnostics
Send Vector's version, operating system, and stack traces to Vector's crash reporting service when the interface crashes. Request, user, breadcrumb, and extra fields are removed; repository files, prompts, terminal output, and provider credentials are not intentionally attached.

Usage counts

Counted under a random install ID, and your Vector account when you are signed in. On by default.

Share usage counts
Sends daily session counts and your token use by model, with your app version and OS. Never your prompts, code or files.

Local data

Preferences and caches stored on this device. Repository files are never touched.

Restore every Vector preference on this device to its default? Repository files are never touched.

Verified completion

Have Vector prove its work matches what you asked before it reports done.

Automatic model routing
Let Vector switch to a stronger model when it judges a task complex. This spends your own provider key at that model's rate, which can be many times higher than the one you picked. Off by default; the composer always shows the model actually in use.
LLM-as-a-judge
When Vector finishes a task that changed files, a separate judge compares the result against your request. On a failed verdict Vector repairs it and the judge looks again, up to three rounds. Choose below which tasks it checks; greetings and questions are never judged. Costs extra model calls.
Tasks the judge checks
Large tasks are the ones Vector runs as Thorough: when you ask it to be thorough, or when the agent raises an exceptionally hard request to Thorough. Ordinary work, even when Vector hands parts of it to subagents, is checked only with "Every task that changes files", which also covers small fixes.

Subagents and subagent specialists

Vector's agent can hand independent parts of a task to other agents and keep working. There are two kinds, and you will see both in the chat and in Background tasks.

Subagents

Turn either kind off and the agent does that work itself.

General subagents
Helpers with the agent's own tools and permissions. It starts them for independent parts of a task, such as reading several areas of the code at once.
Subagent specialists
Named agents with one focus each, such as Review or Test, and only the permissions that focus needs. The agent picks one when the job fits.

Subagent specialists

Named agents with one focus each and the permissions to match. To ask for one yourself, type @ and its name in the composer.
