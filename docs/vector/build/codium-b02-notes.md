# B02: workflow and helper labels

Contract recorded before implementation, 10 November 2026. Base: `eed4bc45a5c24c87d9d9505306c048ba9ebec3c7`.

The approved requirements are `codium-build-spec.md` B02 and `codium-label-plan.md` C13 / section 11. Workflow insight cost cells and explanations identify Codium without presenting its token counts or dollar cost. The busy note must account for helpers using the user's provider keys or Vector Codium plan.

Workflow learning keeps its existing internal token measurements. Display provenance must cover every observed step, including Codium helpers under an own-key parent: checking only the arm's primary provider would leak inclusive token averages. `ArmStats` and its Memory API representation gain optional `codium: "only" | "mixed"`. Positive `costKinds` counters establish the sources; the primary provider is a fallback only for legacy observations with no positive counters. Aggregating observations or combining comparison arms preserves this provenance. Non-Codium arms omit the field.

Pure Codium displays `Codium`. Mixed observations display the existing own-cost figure followed by ` + Codium`; when no priced own runs exist, that figure is `unknown`. Optional `ownUnpriced: true` preserves unknown own spend beside an average from separate fully priced runs (`avg $X + unknown + Codium`). Existing dollar averages still describe only fully priced runs, not an invented price for mixed or incomplete runs. Explanations suppress inclusive token averages whenever any Codium is present. Provider fallback also protects historical advice without the new marker. No learning thresholds or model-selection behavior change in B02.

The Memory HTTP boundary omits Codium-inclusive `tokens` from both arm rows and advice bases, and omits historical Codium-only dollar placeholders. It leaves internal learning values and raw archives intact. This follows label-plan section 4.4's rule for totals and summaries; missing figures are absent, not zero. The new provenance fields describe display only: a legacy provider fallback must never prove B04's all-Codium weighted usage.

A zero-dollar average is retained only from fully priced recorded runs. Free and OAuth-plan observations, including mixed Codium work, are stored without a dollar amount and never become a zero-dollar average. No formatter infers the credential type or claims a request ran on the user's keys. The store regression covers free and plan rows explicitly.

Existing task progress, notification, helper and concurrency surfaces are audited against the merged A25 implementation. Public API changes require the normal SDK and typed-client generators. Focused validation covers all-Codium, own-key parents with Codium helpers, mixed observations, legacy provenance and unchanged own-key output, plus the busy-note regression.

The existing `TaskManager` projection removes a pure Codium workflow's token gauge; `test/task/manager-workflow.test.ts` already asserts that its formatted result says `Codium` without tokens. Judges launched by `SessionPrompt.launchJudge` use the ordinary task path, whose shared `CodiumUsage.taskText` and task-board display preserve Codium labels. Notifications print only proven own tokens. Gateway concurrency refusals already say “Your Codium requests are busy. Wait for a request to finish and try again.” and `ModelPlanStatus` classifies that refusal as a retryable wait; that distinct gateway limit is never described as a subagent slot.

Validation completed on 10 November 2026 in isolated temporary XDG directories, with one serialized local Bun workload at a time. The normal legacy SDK build and typed-client generator passed. Core, Engine and App package typechecks passed. The following 26 focused cases passed: Core `brain/workflow.test.ts` (14), App `memory-workflow-model.test.ts` (8), Engine `server/memory-workflow.test.ts` (3), and the single changed busy-note case in `tool/task.test.ts` (1). The complete tool suite was not run locally. The coordinator independently reviewed the source and the zero-dollar provenance clarification. Native CI remains the next integration gate.
