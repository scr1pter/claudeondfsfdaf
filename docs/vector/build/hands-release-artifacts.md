# Vector Hands release artifacts

C7 packages helpers from the native workflow in the same GitHub run. Helper artifact names use the release tag, without an attempt number. Stable releases use the `prod` desktop and helper identities; prereleases use `beta` for both, including `Vector Beta.app`. Production artifact suffixes retain the tag; beta suffixes append `-beta`. The reusable native workflow validates its `helper-channel` input (`prod`, `beta` or `dev`, default `prod`); development suffixes append `-dev`. A production helper cannot be relabeled into a beta or development helper. Each restore checks the artifact's run, commit, repository, id and digest, downloads it with `gh run download`, checks the archive, then extracts with `tar -xpf` into an empty directory. Missing first-attempt artifacts allow a build; incomplete, expired or changed artifact sets fail instead of being replaced. Required native checks run again on restored shipping/test bytes.

The macOS package step verifies the original ad-hoc helper signature and exact channel source before C4 signs the packaged copy. Production additionally requires the enforced measured production source digest and per-architecture cdhash lock. Beta and development helpers have their own channel source digest, bundle identifier, display name and icon; they must match the measured production helper version and toolchain, while their independently verified source and signature must match their actual channel. The production cdhash is not reused as a beta/development baseline, and only a production measurement can emit a production lock candidate. Final verification checks each app's helper signature, empty entitlements, runtime, exact requested channel, source and sealed signing receipt. Developer ID helpers also undergo Gatekeeper assessment. The original native artifact remains unchanged.

Windows retains two immutable stages: the tested unsigned native helpers, and the final helper copies after optional Trusted Signing. The final copies are restored before any second signing attempt. The signing script runs once for both architectures, before Main's helper hashes compile. A PE content digest permits only the checksum, certificate-directory fields, appended certificate and alignment padding to change. Source metadata, architecture and executable content must match the tested originals. Final manifests contain the hashes of the bytes that ship; electron-builder excludes the helper from another signing pass.

The x64 packaging runner verifies both Authenticode statuses and executes the x64 final verifier. A separate Windows ARM64 job restores the exact packaged ARM64 `resources/app.asar`, helper and manifest by artifact id/digest and runs the final verifier there. It reads the actual compiled Main pins and executes the native helper's version and packaged self-test. Publishing depends on that job. The proof archive remains a CI artifact; the public release asset allowlist is unchanged.

## Signing configuration

Signed releases need the existing Apple/Azure credentials and `VECTOR_WINDOWS_PUBLISHER_NAME` for Electron/updater signing. They also require the public repository variable `VECTOR_COMPUTER_HELPER_PUBLISHER_SUBJECT`: the exact complete certificate subject DN expected for the Azure Trusted Signing profile. This is separate from a company display name. Obtain it from the independently trusted profile/certificate configuration, using the same full `X509Certificate2.Subject` serialization returned by Windows. Do not set the expected value by copying it from the helper being verified. Missing or different subjects fail a signed release; an unsigned preview does not need this variable.

Existing protected-source, protected-environment and allowlisted unsigned release policy remain in force for normal releases. C7 does not add an unsigned release version or authorize publication.

## Artifacts-only preview

`workflow_dispatch` can select `dry_run: true` only on the same repository's `hands` branch, with explicit `allow_unsigned: true` and the stable channel. It builds and verifies Actions artifacts. It receives no production signing/feed secrets and cannot enter the protected publishing job or mutate tags, channels, update feeds or deployments. The ordinary release tag/version and changelog checks still apply; changed measured helpers require the macOS access re-ask caveat in that release's desktop notes.

The source and structural checks do not establish that a preview has packaged successfully. Record the actual run, commit and per-platform outcomes after executing this path. Production signing, notarization, owner OS checks and release approval remain separate evidence.
