# B03: explicit consent for Brain helpers

Contract recorded before implementation, 10 November 2026. B02 source was independently reviewed; its exact patch and notes are checkpointed in the coordinator's scratch directory while its validation waits for the shared test slot.

The governing requirements are `codium-build-spec.md` B03 and section 4's setting default, plus `codium-tiers-v3.md` T and decision 8 as amended by the later build spec. Codium Brain helpers require the owner's explicit opt-in. `ask` is the initial state; neither subscribing nor choosing a Codium conversation turns the helpers on.

The approved location adjustment is to store `codiumHelpers: "ask" | "on" | "off"` in the authoritative personal Brain settings, surfaced through Memory's owner API and the app. An independent app-only preference could leave the CLI, another client or a delayed helper using stale permission. No repository configuration can grant consent. Helper requests re-read the setting before sending content; existing learning-off, guest, taint, untrusted-repository, trainable-provider and run-budget protections continue to apply. An explicit helper-off setting wins over Codium consent. Vector Local continues to use local helpers and never switches onto Codium.

With consent on, a helper may use only an unlocked, non-manual Codium model whose trusted catalog metadata explicitly says `role: "floor"`. Auto's floor pointer and the ordinary helper selector may fall back to a default model, so they cannot authorize this choice. No eligible floor means skip, with no fallback to the primary or another paid route. The gateway already qualifies served Codium routes for zero data retention. Brain calls carry purpose `brain`; a Brain-share refusal quietly leaves the plain draft or produces no proposal.

Distillation becomes an ordinary personal setting, off initially; the legacy development flag is only a fallback until the owner saves an explicit setting. Explicit off wins over that flag. Distillation remains quote-locked and bounded. The explicit “Bootstrap this repo” action scans the repository's existing eligible tracked-document path and sends only bounded selected sections to the chosen model; results stay proposals for review. Its model helper obeys the same Codium consent/floor rules, and it remains available with the owner's own model.

The app asks once after a confirmed subscription when the capability exists, offers an explicit yes/no choice, and exposes the same setting in Memory. Old engines without the capability cannot be treated as having permission. Privacy and Brain documentation explain the opt-in model request, explicit Brain attachment to owner-started GitHub runs and encrypted Vault backup without claiming that any unreleased transport is already available.

This implementation does not change live listing settings. The server's readiness registry can recognize the completed client capability only once B03's consent, helper, distillation, Bootstrap, UI and documentation work is validated; existing release and `CODIUM_TRACK_B_LIVE` gates remain required. Validation will use local fixtures, never paid requests.

The completed UI additionally requires a fresh status listing `brain` before showing Codium controls or asking for consent, and rechecks access before enabling or sending a confirmed Codium Bootstrap request. Own-model document suggestions remain available independently. Presentation history is scoped to account and engine and cannot authorize a request. Each confirmed document request preserves the exact previewed model and section bound; a changed floor requires a fresh preview. A partial successful HTTP response carrying a model error preserves its proposals and stops the remaining batch.
