# A49 Ship Desk and capture: implementation record

A49 builds on A47 (the webhook router, its ops handler and `registerShipDeskIntake`), A48 (one-repository App tokens,
the ops records helpers and the `ops` provisioner), A37 (R2 presigning and server phone alerts) and A38 (the phone app
that will show the cards, A50). It adds Ship Desk's cards, the capture API and its ticket, the image route, and the
`vector ship` command. No GitHub, Cloudflare, Stripe or Supabase API was called: the tests run the routes against the
fake GitHub API in `test/ops-fixture.ts`, an in-memory `vector-media` bucket that checks every SigV4 signature, and the
Codium fake store. Readings of the contract are in `codium-deviations.md` under "A49 Ship Desk and capture (4 Nov
2026)".

## Interfaces for later packages

- **Codex, V31** (the capture job, `packages/core/src/review/workflow.ts`): add `vector ship ticket` to the agent job right
  after the mint step and before checkout (it reads `$RUNNER_TEMP/vector-secrets/run-token`), expose
  `capture: ${{ steps.<id>.outputs.capture }}` from the agent job, and run the **Vector capture** job (no `id-token`, no
  run token, `contents: read`) after publish when `vars.VECTOR_SHIP_DESK == '1'` and the output is not empty:
  check out the pull request's head with `fetch-depth: 0`, then `vector ship capture --pr <n>` with
  `VECTOR_CAPTURE_TICKET: ${{ needs.agent.outputs.capture }}`. The capture exits 0 when there is nothing to capture.
  Pull requests must keep the `<!-- vector:rid <rid> -->` marker; a later run on the same pull request should write its
  own marker (the card follows the newest checked run).
- **A59**: `registerCloudRunReader((account, input) => listCloudRuns(account, input))` now also feeds Ship Desk; records
  must keep `rid`, `repositoryId`, `runUrl`, `endedAt` and `verdict` as in Codex's spec 2.16.
- **A50** (screens): `/api/ops/cards` and `/api/ops/image/<card>/<n>` (fetch the JSON with the account's credential, then
  use the signed link in an `<img>`; it lives 60 seconds). Approve: open `approve.url`, or merge in the desktop with the
  person's own GitHub sign-in, checking `approve.headSha`. The `ship-desk` readiness check in `perkServices`
  (recommended: `opsConfigured() && githubServerConfigured() && r2Configured("media")`). The cleanup cron can rely on
  cards expiring by themselves; images expire by the bucket's lifecycle rules.
- **A57**: account deletion gets Ship Desk through the `ops` provisioner; `eraseAccountShipDesk(account)` can also be
  called directly.

## P7 review fixes (5 Nov 2026)

- **Private repositories only.** `mintCaptureTicket` reads the repository's visibility with a read-only `ship` App
  token (reason `ship-ticket`, revoked and audited like the others) and refuses a public one with 403
  `SHIP_DESK_PUBLIC_REPOSITORY`: GitHub prints a step's environment in its log, so the capture job's log shows the
  ticket. GitHub unreachable is 503 `GITHUB_UNAVAILABLE` (no ticket; the capture job does not run).
- **The ticket is bound to its first caller.** `vector ship capture` makes a random 32-byte proof (`ShipDesk.PROOF`)
  and sends it as `proof` with every request; the server stores its SHA-256 on the ticket (`proof`, `boundAt`) at the
  first request of any action, and answers 403 `SHIP_DESK_TICKET_BOUND` to any other proof, 400 to none. The 15-minute
  upload window still opens at the first `start` (codium-deviations.md, "P7 review decisions"). For Codex's V31: no
  change to the wiring; a re-run of the capture job alone is refused (new proof), a re-run of the workflow mints a new
  ticket.
- **Listing.** A new card and a capture ticket need `ship-desk` listed or the account in `VECTOR_OPS_ALLOW_ACCOUNTS`
  (intake `not-listed`, ticket 503 `OPS_UNAVAILABLE`); a card made before keeps following its pull request.
- **Tests:** `test/ship-desk.test.ts` (25 pass, 1 CI-only skip; the helper sends one proof per ticket): the binding (no
  proof, a short one, another one at card, start and finish; only the hash stored; no window opened by `card`), a public
  repository refused with the token revoked, GitHub down, unlisted refused, the intake's `not-listed` without a token
  minted, and an existing card updated while unlisted. `packages/engine/test/cli/ship.test.ts` (11 pass): every API
  request carries one proof, never in a child's environment.
