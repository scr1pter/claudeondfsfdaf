# A47 GitHub webhook router and ops settings: implementation record

A47 builds on A46 (the ops Worker), A37 (the internal HMAC and safeFetch) and A05 (the entitlement snapshot). It adds the
shared GitHub webhook router, Codium's ops handler on it, and the ops settings routes for domains, On Call URLs and
Release Guard / Ship Desk repositories. No GitHub, Cloudflare, Stripe or Supabase API was called; the tests run the
router, the routes and A46's own Worker code in memory. Readings of the contract are in `codium-deviations.md` under
"A47 GitHub webhook router and ops settings (4 Nov 2026)".

## What changed

| Area            | Change                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Router          | `api/_lib/github-webhook.ts` and `api/github/webhook.ts` (`bodyParser: false`). In order: the `x-hub-signature-256` HMAC over the raw body under `VECTOR_GITHUB_APP_WEBHOOK_SECRET` (constant time, 503 without a secret of 32+ characters); the event filter (a `ping`, or an event no handler named, answers 200 before any store read); the dedupe by `x-github-delivery` (pending 60 s, done 7 days; a failed delivery is freed and answers 500); then every handler that named the event, at once, each with its own parse of the payload and 8 s. Bodies over 2 MiB get 413. A failing handler is logged by handler id, delivery id and error code, never the payload.                                                                                                                                                                                             |
| Handler shape   | Codex's spec 2.14: `GithubWebhookHandler = {id, events, handle(event)}`, `GithubWebhookEvent = {name, action?, deliveryId, payload}`. The route's `GITHUB_WEBHOOK_HANDLERS` list holds `opsWebhookHandler`; A59 adds `cloudAgentsWebhookHandler`. Handlers are checked when the route loads (unique ids; only `installation`, `installation_repositories`, `repository`, `pull_request`, `deployment_status`).                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Ops handler     | `api/_lib/github-webhook-handlers/ops.ts`. `deployment_status` success in the environment a bound repository's settings name (no case, not transient), Release Guard on, plan with `caps.ops.releaseGuard` now, ops configured and switched on → the Worker's `release` with the production URL joined with each path, on verified domains, at most the plan's paths. `pull_request` (opened, reopened, synchronize, ready_for_review, closed) by `<VECTOR_GITHUB_APP_SLUG>[bot]` from the same repository, Ship Desk on → the intake A49 registers (`registerShipDeskIntake`). `installation.deleted`, `installation_repositories.removed`, `repository.deleted` and `repository.transferred` → drop those repositories' settings everywhere. Unknown payloads are ignored; only an unreachable store or Worker throws. `routeOpsEvent` answers the outcome, for tests. |
| Bindings        | `registerRepoBindingReader` in `ops-settings.ts`: a repository's owner is Codex's binding (`bindingFor`). A59 registers it. Until then nothing is bound.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Settings        | `api/_lib/ops-settings.ts`. One JSON document per account, `ops:settings:<account>`, changed only by the SAVE compare-and-set script, which also keeps `ops:repo:<repositoryId>`, `ops:installation:<installationId>` and the `ops:domains:due` sorted set. Every stored field is checked on read (503 `OPS_SETTINGS_UNREADABLE` otherwise). `syncOpsConfig` sends the Worker's `config` when its hash changed. `dropOpsRepositories` and `eraseAccountOpsSettings` (both modes, for A57).                                                                                                                                                                                                                                                                                                                                                                               |
| Verification    | `api/_lib/ops-domains.ts`. TXT `_vector-verify.<domain>` = `vector-verify=<token>` over Cloudflare's DNS-over-HTTPS, or the same line in `https://<domain>/.well-known/vector-verify.txt` through safeFetch (no redirects, public addresses only). Outcomes: verified, failed, inconclusive. Host names follow the Worker's rules exactly.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Routes          | `api/ops/domains.ts` (GET; POST `{domain}` adds; POST `{domain, verify: true}` checks; DELETE `{domain}` also removes its monitors; GET with `CRON_SECRET` is the daily job), `api/ops/monitors.ts` (GET, POST `{url}`, DELETE `{id}`), `api/ops/repos.ts` (GET with `opsId` and `bound`; POST `{repositoryId, environment, productionUrl?, paths?, releaseGuard, shipDesk}` answers the `.vector/ops.json`; DELETE `{repositoryId}`). Logic in `api/_lib/ops-api.ts`.                                                                                                                                                                                                                                                                                                                                                                                                   |
| Plan rules      | Adding needs `VECTOR_OPS_ENABLED`, the Worker's URL and secret (503 `OPS_UNAVAILABLE`), the `ops` switch (503 `OPS_PAUSED`) and `requireEntitlement(account, "ops")` (S1). Counts from the snapshot's `caps.ops`: domains and URLs from `onCall`, paths from `releaseGuard`; 429 `OPS_LIMIT {limit, max}`. Monitors and Release Guard production URLs only on verified domains (403 `OPS_DOMAIN_UNVERIFIED`). Repositories only while bound (409 `OPS_REPO_NOT_BOUND`), at most 20. Reading and removing work whatever the plan. Callers: an unrevoked `vct_` token or a website session; run tokens get 401 (S3).                                                                                                                                                                                                                                                       |
| Weekly re-check | The daily job (`vercel.json`: `/api/ops/domains` at 04:10 UTC) checks each verified domain 7 days after its last success, retries an unreadable check daily, ends verification on a failed check or 14 days after the last success, and resends Worker updates that failed. One account's failure never stops the others.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Worker client   | `api/_lib/ops-worker.ts`: `opsConfigured`, `requireOpsService`, `opsCall` (any action, 503 on anything but a 2xx JSON object), `opsConfig`, `opsRelease`, `syncOpsKillFlag`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |

## Interfaces for later packages

- **A48** (Release Guard and incidents): `opsRelease` and the deployment path in `github-webhook-handlers/ops.ts` are the
  place to add the `.vector/ops.json` re-read (compare its `opsId` with the account's, from `readOpsSettings`) and the
  API-side daily cap. The ops provisioner (`plan` from the snapshot, per A46's notes) and the `on-call` and
  `release-guard` readiness checks are still to build (A48 or A50). `opsCall` takes any Worker action.
- **A49** (Ship Desk): `registerShipDeskIntake(intake)` gets `OpsPullRequest {account, repositoryId, repository, number,
action, headSha, merged, draft, url, installationId?, deliveryId}` for App-bot, same-repository pull requests in
  repositories with Ship Desk on. The intake checks the plan (§4.4 Ship Desk row) and counts cards once per (repository,
  pull request). Codex says its pull requests are `github-actions[bot]`-authored by default; widening the filter is
  A49's decision.
- **A50** (ops UI and crons): the screens read the three routes. The daily `/api/ops/domains` job is where the
  certificate, domain expiry and DNS drift checks go (`reverifyOpsDomains` is its first part).
- **A57**: call `eraseAccountOpsSettings(account)` and the Worker's `erase` on account deletion.
- **A59**: `registerRepoBindingReader((id) => bindingFor(id))`, and add `cloudAgentsWebhookHandler` to
  `GITHUB_WEBHOOK_HANDLERS` in `api/github/webhook.ts`.

## P7 review fixes (5 Nov 2026)

Adding a domain, a monitor or a repository now also needs the perk it serves listed (`api/_lib/ops-listing.ts`;
domains On Call or Release Guard, monitors On Call, a repository each of Release Guard and Ship Desk it turns on), or the
account in `VECTOR_OPS_ALLOW_ACCOUNTS`; otherwise 503 `OPS_UNAVAILABLE`. `requireOpsCaps(account, perks, fetcher, now)`
takes those perks. The deployment handler ignores an unlisted Release Guard (`not-listed`). `requireOpsCaller` returns
the token's `client` marker. Details and tests: the A48 notes' "P7 review fixes" and `codium-deviations.md`.
