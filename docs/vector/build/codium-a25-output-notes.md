## Accounting and desktop records

Desktop spend events, folded days and windows carry an optional Codium marker for mixed activity. Only own dollars and own tokens enter those totals. Codium-only runs append no dollar-ledger event; later Codium activity can annotate an existing mixed event without adding a second charge. The run projection compares before/after counters and the current guard, so a recurring session's previous Codium activity does not label a later own-key run.

Known positive guard spend is retained even when the same run has unknown own work or its session total was reverted, unavailable or lower: measured own cost is the larger available subtotal. Unknown own work remains `costKind: unknown`, independently of `billing: codium`. This separation flows through optional `Task.Info.billing`, desktop IPC/preload and Agent Desk. The task bridge carries known cost and unknown status without inventing token usage.

Initial and old desktop cards can project Codium from their existing pinned Vector provider. In particular, an old pinned Codium `$0.00` card renders Codium. A same-zero own-provider record is not relabelled. This read projection does not persist provider inference as measured activity. A23's admission gates remain intact: resumed scheduled agents inspect the actual session model; parallel workspaces use the provider pinned to the new session they create.

Independent C8 review found and closed the positive-guard-subtotal, direct-card unknown-status and legacy zero-price projection cases. Regressions preserve the own subtotal and unknown/free/plan wording alongside Codium.

Verbose model output uses the billing marker instead of zero catalog rates.

## Structured boundaries

- `run --format json` projects root and subagent step-finish parts with `billing: codium`, `cost: 0`, `unpriced: true` and no tokens. The internal part is unchanged.
- Task list/inspect/wait JSON omits aggregate tokens unless the authoritative task observation carries own-only provenance. Modern own usage and the raw API result are unchanged.
- New, cached and failed review JSON outcomes omit Codium numeric cost/token fields. Mixed aggregates retain known own dollars; explicit own passes retain their own figures. A legacy aggregate that cannot partition tokens omits those aggregate token categories. A26 still owns human review footers and durable per-pass cost-kind state.
- ACP sums only own steps for per-response usage, including aborted responses, and sends no `usage_update` while the latest step is Codium, even if it has zero output and an older own response supplied the last context sample. Existing cost omission when any step is unpriced/Codium remains in force.
- Codium document-distill estimates, results and History omit token/cost figures. Internal estimates remain available for context checks. Old stored History is also projected on read using explicit billing/cost kind or the recorded Codium provider prefix; document and record history preserve own receipts and leave stored bytes unchanged. Public HttpApi/SDK fields are optional for that reason. CLI human and JSON distill output preserve the distinction; own responses retain their measurements.
- Legacy `export --sanitize` removes Codium assistant/step tokens and unsafe legacy session totals, including an explicit Codium step under an older own-provider assistant and migrated zero counters. Partitioned own totals and own parts remain; the raw backup object is not mutated. Native sanitized export already uses the public preview and is unchanged.

## Historical accounting compatibility

A22 intentionally retained old flagless Codium tokens in stored aggregates. A later modern Codium step, a current own-provider model, a version string, or the absence of surviving Codium messages cannot establish that those aggregates are own-only. Deleted and compacted history make provider-based migration insufficient.

The amendment adds independent `tokens_own_only` and `subagent_tokens_own_only` columns, both defaulting to false for every existing row. Only a newly inserted, empty native session can become known, from the nonserialized Created commit callback inside the same immediate transaction. The callback checks sequence zero, no prior event/sequence, zero accounting and no messages, parts, pending inputs or children. Duplicate creation fails before the callback. Imported or replayed Created data and caller-supplied proof fields never certify a row.

Proof only falls after creation. Unattributable contributions, copied/forked history, imports and accepted replay invalidate the relevant own/delegated proof and ancestor delegated proof, even for zero deltas or an already-proven destination. Ignored duplicate replay does not mutate proof. A later own step, a revert or deletion never recertifies it. Flagless compaction without model identity remains unknown. Raw usage, stored billing flags, financial admission and historical event bytes keep their existing accounting behavior.

Session snapshots expose optional `tokensOwnOnly`/`subagentTokensOwnOnly`; Task usage exposes an optional proof for the quantities it includes. Display/export consumers require true proof for aggregate figures even when there is no remaining Codium evidence. They may retain independently identified own-message totals and proven loaded child totals. Older own-only sessions without such evidence therefore show unavailable token totals until a trustworthy independent subtotal is available; missing proof is deliberately not treated as proof of purity. Desktop before/after token deltas are omitted when either reading includes an ambiguous positive component, while known own dollar subtotals remain.

Raw-message output uses the shared `Billing.hasOwnIdentity` predicate. It requires a canonical, nonblank, non-Codium provider identity; padded Codium IDs cannot become own usage. App and TUI context numbers, CLI statistics/export/run JSON and ACP updates apply this separately from aggregate proof. Unidentified raw messages cannot borrow a session’s aggregate proof or an earlier own context sample. Codium context continues to show only its percentage. Editable lifecycle metadata cannot certify task token totals: cards use authoritative Session/Task observations or positively identified loaded messages. Repeated task rows still count the current proven cumulative child subtotal once.

Codium labels use separate activity evidence. Parent-only Codium does not label delegated own work; Codium helpers do not label an unrelated own subagent remainder. Known own unknown-price status and proven child token subtotals survive mixed delegated projections. No eager history scans or new polling were introduced.

Public legacy Created/Updated event snapshots pair proof with the same canonical post-projector accounting row, including tokens, counters and costs. They never combine a raw serialized aggregate with authoritative true proof. Global sync payloads retain the original event bytes exactly; `/sync/history` remains replay-exact. Forwarded remote UI snapshots have local proof stripped. Native durable history does not include legacy Created/Updated snapshots. The minimal inherited identity preflight rejects nested Session/message/part IDs that disagree with their envelope before projectors/listeners, and validates the complete replayAll batch before its first projection.
