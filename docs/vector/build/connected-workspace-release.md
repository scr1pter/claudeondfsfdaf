The engine reads `bool(name)`, which is `Config.boolean(name).pipe(Config.withDefault(false))` (engine `effect/runtime-flags.ts`:4). `Config.boolean` decodes through effect's `Config.Boolean` schema (`node_modules/effect/src/Config.ts`:939-970, effect 4.0.0-beta.83): the case-sensitive literals `true`, `yes`, `on`, `1`, `y` are on and `false`, `no`, `off`, `0`, `n` are off; any other set value, the empty string included, fails the flag layer, and only an unset key takes the default. **Connected tools**

[Release label: the owner adds it with Q1, from `packages/web/src/data/vector-releases.ts`.]

The agent can hand one piece of work to another tool in your workspace and get the result back in the same conversation. Today that is a VectorScope review of your changes.

_See what is connected._ Connected tools are listed in the desktop app under Settings > Agents, in the Connected tools card; in the terminal app with the session command "Connected tools"; and from the command line with `vector connected list --attach <server URL>`. Each row says where the tool runs, where it sends your code, and whether it is ready. A tool that is not ready says why. [app `components/settings-v2/subagents.tsx`:511-512 and `settings-registry.ts` ("Agents"); tui `routes/session/index.tsx`:489-497; engine `cli/cmd/connected.ts`]

_Review your changes._ Type `/vectorscope` (uncommitted changes), `/vectorscope staged`, `/vectorscope branch` or `/vectorscope branch <base>`, or ask the agent for a VectorScope review. The review runs in the background. The Background tasks pane in the desktop app shows its status and verdict while it runs, with Cancel. From the command line, `vector connected runs` and `vector connected cancel <run>` do the same against a running server. `vector connected review` needs a server running on the Node engine, such as the desktop app's; a server started with the `vector` binary answers it with "Connected reviews over this server's HTTP listener require the Node engine." When the review ends, the agent reports the verdict, where the diff went and what the review cost, then lists the findings. Findings are a reviewer model's claims about the code; check them before you act on them. [engine `command/template/vectorscope.txt`; app background-tasks pane (CN-12); `cli/cmd/connected.ts` `CONNECTED_ACTIONS`; `server/routes/instance/httpapi/handlers/connect.ts`:18-24, only the two review starts use `withRequestAbort`; `test/server/httpapi-connect.test.ts`:566]

In the desktop's agents view, a workspace card can also start a VectorScope review of that workspace's folder. Its approval is asked in the desktop. [app `features/connect/directory-review.tsx`, used by `features/agents/agent-dashboard.tsx` and `external-agent-workspace.tsx`]

_What Vector asks first._

- A read-only review on a model you chose asks nothing when it sends your code to this computer, to your own model server, or to a review model of yours with a price of zero. Your own permission rules can still make it ask or deny it.
- A review on a priced model, a model whose price Vector cannot read, or a review or triage model that the repository's review.json picks, asks once for that request (`connect_model`). You can save that answer for the model. [core `connect/policy.ts` `modelConsentReason`:195-202 and `CONSENTS.connect_model.when`:152]
- A fix asks every time (`connect_write`). Auto-accept and saved approvals never answer this question. [core `connect/policy.ts` `CONSENTS`; engine `agent/agent.ts`:361-363; schema `permission-policy.ts`:9 and :173. Exception, §1.3: a 1.99.111 client attached to a newer engine can auto-accept it]
- If the changes touch a file that one of your read rules denies or asks about, the review stops before anything is sent. [spec §10, I1 and I3. Exception, §1.3: an absolute read deny written with another spelling of the repository's path is not applied]

_Fixes._ When you ask for a fix of chosen findings, a fix helper works in its own copy of the repository. It cannot run commands, and its change is applied only after you approve it. [engine `agent/agent.ts` `connect_fix`; core `connect/policy.ts` `fixAgentRules` (shell denied); `connect_write` always asks]

_Settings._ In your Vector config, under `connect.review`:

- `after_run`: `off` (the default) or `report`, a review after the agent changes files. `repair` is reserved and only reports for now.
- `before_commit`: `off`, `offer` (the default) or `run`, what the agent does before it commits, pushes or opens a pull request. This is guidance for the agent, not a commit guard.
- `max_rounds`: 1 to 3 review rounds per request (default 1).
- `max_cost_usd`: the most one review may spend, further limited by the conversation's budget (default 2).

A repository's own config can only turn reviews down or lower these limits. [core `v1/config/connect.ts`, `Defaults`; spec §10, I12]

_Vector Local._ With Vector Local on, a connected tool that runs on Vector's servers or in your own cloud accounts, that sends your code or screen to a Vector cloud service, or that would send your code anywhere other than this computer or a model server you listed, is listed as off, and the agent does not hand work to it. [core `connect/policy.ts` `localGate`:360-378; schema `connect.ts` `isLocal`:58]

_Limits._

- Reviews need Linux for now. On macOS and Windows, VectorScope is listed as unavailable with that reason.
- If VectorScope is listed with "Open this project through its real folder path to use connected reviews.", reopen the project at its real folder. [engine `connect/git.ts` `LINKED`; deviations "C2 remainder: projects opened through a link (CN-06)"]

- A branch review's base can be a branch, remote-tracking branch or tag name, or a commit id of 7 to 40 hex digits. A short commit id must name exactly one commit and must not also be a branch or tag name. A name of fewer than 7 hex digits is used only when a branch or tag has that name. With no base, the branch is compared with its merge base against the branch `origin/HEAD` names; if `origin/HEAD` is not set, name a base. [engine `connect/git.ts`:83-90 and :271-282; core `read-only-git.ts`:1726-1755 and :1924-1940; deviations "C3c: connect branch reviews accept named and default bases (CN-05)"]
