# Separate matched-team development study

This four-role, three-maintenance-task plan was superseded **before any paid
team call** by the owner's request for substantially heavier nested workflows.
It remains as a historical preregistration. The replacement is the
[heavy-team stage](../agentic-heavy-v1/STAGE.md); none of the free protocol
proofs below is a funded product result.

Recorded November 2, 2026, before any funded native-team call. The user explicitly
authorized this study separately from the completed single-agent comparisons.
The objective remains at least 20% lower complete-delivery API cost, conditional
on preserving quality. The previous single-agent result is not pooled into this
team result.

## Fixed inputs and teams

Vector uses clean product revision
`479303cf229badc0fa2c770f27d7d845dfa4fa68`. Codex uses CLI
`0.166.0-alpha.5.1`, executable SHA256
`3097c909fb6d5cd63510d44aceb1d42df9f6e85722a3e447e477def1ecf60e16`.
Every inference uses `gpt-6.1-sol`, High reasoning, automatic reasoning summaries,
low verbosity, 1,050,000 context and a common 32,000 output ceiling. Explicitly
smaller native helper output quotas remain smaller; no model or effort routing
is introduced to manufacture savings.

Each runtime has one lead, two fixed workers (`backend_worker`,
`frontend_worker`) and one fixed `team_judge`. Backend and frontend file ownership
must not overlap. Both workers finish before the judge begins; the lead fixes
material findings and personally verifies the final API and browser UI. Follow-ups
reuse the same native identities. Additional identities, replacements and nested
delegation are refused before inference. All helpers, repairs and failed calls
remain billed. File ownership and read-only judge instructions are prompt policy;
this is not an operating-system filesystem security boundary.

Vector uses Thorough to expose its native TaskTool, with its automatic judge off.
The equivalent Codex collaboration feature is enabled. Neither command has an
additional native dollar cap. Both receive the same common browser client and
capabilities. Raw browser libraries and connections are withheld from runtime
environments. Bounded transcript/script inspection remains necessary; unrestricted
shell execution is not an operating-system sandbox.

## Spending and process bounds

The existing ledger starts this stage at 889 requests / $20.3038291. Cumulative
Vector actor spend is $10.8884618 and Codex actor spend is $6.4715992. These are
settled historical checkpoints, not current invoices or fresh allocations. The
original $48 study cap and cumulative $20 per-runtime actor caps remain unchanged.
No old charge, actor, failed attempt or reservation may be reset or reclassified.

Each arm permits at most 300 provider requests, two hours of agent execution and
one formal repair in the same lead session. The $3 threshold is checked only
after a settled invocation when deciding whether to admit that repair; it never
stops a running invocation. The cumulative funding caps, conservative reservation
checks and request/time limits remain hard constraints. Every overshoot of the
repair threshold is retained.

Before each arm, settled global and actor headroom must both afford the existing
full-quality $5.73 conservative image reservation. Actual per-request admission
remains in force. Insufficient headroom means **not run**, not a reason to disable
images, reduce effort or skip verification. A budget stop leaves the fixed set
incomplete and the efficiency objective unmet. Do not run calls merely to fill
an allowance. Only one Bun workload runs at a time.

The supervisor owns the real scoped funding capability; a coding runtime sees
only a different local alias. Native ancestry is joined before forwarding.
Accepted requests are drained and reconciled against all actor/label/batch/sequence/
request-hash receipts at closure, including child inference absent from a lead
CLI usage footer. Unknown usage, ambiguous closure or a policy failure blocks
the next arm. Known-length incomplete responses can continue within the current
arm under the same limits but require explicit review at closure. No uncertain
request is automatically retried.

## Acceptance and retained evidence

Every required independent functional check must pass. After each completed pair,
an independent reviewer receives opaque labels, the same public task/seed, exact
delivery source and matched independent screenshots, using the unchanged
[48-point rubric](quality-rubric.md). The same reviewer evaluates both arms
without runtime identity, cost or the optimization hypothesis. The source score
must be no lower for Vector on **each task**, with no established new critical
regression. A stronger task cannot compensate for a weaker one. Static review
and supplied images have bounded coverage and do not prove production readiness.

Native-team chronology/browser telemetry is a separate execution audit. Its
passing flag is not a semantic code-quality score. Cost and efficiency claims
stay false until every fixed pair, functional gate and blinded review is complete.

Free qualification uses dummy-only loopback inference, the actual native adapter
commands and the real unchanged Workflow Runner seed. A labelled fixture page/API
tests shell and common-browser capabilities; it is not a benchmark delivery.
The real evaluator must remain negative on that unchanged seed. Qualification
also requires all four native identities, pinned settings, reconciled receipts,
unchanged source and clean closure. These checks make zero real provider calls.

All failed, stopped, unaffordable and not-run arms remain reported. Any later
product fix creates a separately frozen candidate stage rather than rewriting
this stage's source or results. Publish completed code, exact synthetic delivery
sources and sanitized evidence to GitHub. Credentials, raw prompts, native IDs,
runtime configurations and company data remain private. No cloud deployment,
release or merge to upstream main is part of this study.
