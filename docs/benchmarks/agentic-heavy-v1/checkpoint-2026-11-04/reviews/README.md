The same fresh reviewer read both source/config/test packages and nine native PNGs each using the same 12 code axes and 10 visual axes (0–4 each). Elm was scored, written and locked before Willow was inspected; its hash is unchanged afterward. Runtime identities, prices, original functional outcomes and posthoc diagnostics were withheld. Authored verdict prose and another reviewer's earlier scores were excluded. The earlier Vector37/48+23/40 review remains a different review pool; scores are not averaged or substituted.

The [Elm report](elm.json), [Willow report](willow.json) and [comparison metadata](comparison.json) retain score arithmetic, citations and limitations. Public projection changes only path formatting/labels, not scores or findings. Evidence `source/` and `screenshots/` paths refer to the mapped submission package.

Elm shows stronger static authorization/typing. Willow has slightly better supplied visual evidence: populated inventory/board and390px mobile screenshots. Both have compressed frontend code, repeated JSON-record scans and file/database crash-recovery risks. Willow's stale-authority concern was source-inferred by this reviewer; the later independent runtime diagnostic remains separate and did not change these scores.

Codex's app is an interrupted snapshot without its final native judge. These scores neither establish a completed matched quality/cost result nor predict every future output. Screenshots do not prove runtime behavior, accessibility or production readiness. External reviewer assistance is evaluation overhead, excluded from both provider task totals; native team-judge provider requests are included when run.
