This is a development replication of a known qualified task, not a new holdout.

not another arm's output or a reference implementation. Use synthetic local data,
owned isolated browser contexts and the common browser client. No cloud deployment,

This is seven autonomous identities including the lead, six immutable lifetime

rejected before inference. Assign nonoverlapping implementation/test ownership;
the lead owns shared-file coordination. The coordinator must finish after both
backend specialists, and the final judge must review the completed workers' work.
The lead corrects material findings and verifies the final API and UI afterward.

Both runtimes use `gpt-6.1-sol`, High reasoning, automatic summaries, low verbosity,
1,050,000 context and a common 32,000 output ceiling for every role. Smaller native
helper output quotas remain smaller. Vector uses frozen product revision
`479303cf229badc0fa2c770f27d7d845dfa4fa68`, Thorough to expose TaskTool, and its
automatic judge off. Codex uses the previously pinned CLI
`0.166.0-alpha.5.1`, including its native programmatic tool composition. No weaker
control, cheaper model, reduced effort or verification cut is introduced to
produce a favorable comparison. Every helper, retry, specialist, judge and repair
request is metered, even if absent from the lead CLI usage footer.

The exact role prose, configuration, source/task manifests, tool binaries and
instrument hashes must be frozen in the reviewed execution plan before admission.
The two product harnesses still have different native prompts and tool interfaces;
that difference is part of the harness comparison. The owned witness serializes
inference forwards equally. Agent runtime is therefore not a measurement of

## Quality first, then cost

Passing all required functional gates is necessary. The independent execution
audit establishes native lineage/chronology and bounded browser observations;
it does not score product quality. Each completed pair separately receives the
unchanged [48-point blinded review](../agentic-workflows-v1/quality-rubric.md), with
opaque identities, the same public task/seed, exact delivered source and matched
independent screenshots. The reviewer must not receive runtime identity, cost or
the optimization hypothesis until scores are recorded.

Vector must have no lower score on each task, all required checks passing and no
established new critical regression. No stronger task compensates for a weaker
one. Only after those gates may at least 20% lower complete-delivery cost count
as meeting the savings objective. Source review, screenshots and synthetic checks
have bounded coverage; none establishes universal superiority or production safety.

Inspect each pair's traces and findings before deciding on another candidate or
task. Do not spend merely to exhaust an allowance. A genuine harness fix needs
focused controls, a new source freeze and a separately labelled measured stage.
Keep every failed, stopped, unaffordable, not-run and repaired case, and all its
charges. Any incomplete pair or failed quality gate means no matched savings claim.

Publish completed source, tests, exact synthetic deliveries and sanitized evidence
to GitHub. Keep keys, controller capabilities, raw prompts, native IDs, runtime
configuration and company data private. No release or merge to upstream main is
part of this work. A later Claude Code comparison requires its own verified model,
matched profile, authorized billing and separately reported study; it has not run.
