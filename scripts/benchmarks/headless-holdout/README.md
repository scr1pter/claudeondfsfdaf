# Independent headless holdout

This is a separate task and methodology from Harbor. Its requested product is an API service with a CLI and typed SDK. It does not request a UI, and it never removes or substitutes for Harbor's browser/UI checks. Both arms must receive the identical empty seed; no reference implementation belongs in the task root, authored workspace or public evaluator.

`original-contract.json` records 50 business acceptance groups, four prerequisites and the original requirements hash, frozen in Git before private reference coding. Requirements remain stable during reference implementation. Instrument corrections must be recorded as corrections, without weakening original requirements. The evaluator runs the actual service, CLI and SDK; it checks failures, authorization, transactional durability, concurrency, restart and corruption as well as successful workflows. It uses only standard Python libraries, an explicitly supplied local JS runtime, and an explicitly supplied offline TypeScript compiler.

`headless_profile.py` derives an instruction-only variant of frozen R1 `r1-profile.json`. Only lead, frontend_worker (the CLI/SDK client role), QA and judge instructions change. Model, high reasoning, context/output limits, seven identities, depth two, role DAG, review/repair rules, caps, all tool availability and conditional common browser safety instructions remain identical. Browser use remains available. The separate task naturally requires CLI/SDK/API verification.

Run source checks with `python -B -m unittest -q test_source_contract.py` from this directory. `evaluate.py --app APP --out OUT --runtime NODE --node NODE --typescript TSC_JS` performs Node authoring prequalification only. It never claims runtime qualification. The later owner-authorized gate must pass `--runtime BUN --mode bun-qualification`; that mode proves the supplied executable actually exposes Bun. Use full absolute executable paths. No packages are fetched. Runtime qualification also requires positive reference, empty seed with zero business passes, and corrupt/stale-authority negative controls. The private reference and qualification outputs live outside this public task root.

The evaluator creates temporary data directories and directly owns every child it starts. Windows starts children suspended, assigns them to an unnamed non-inheritable kill-on-close Job Object, then resumes them. The job contains descendants even if they detach or the initial process exits. It requests graceful shutdown via the service child's stdin, then closes ownership unconditionally and joins output readers. It never enumerates/terminates unrelated processes or uses process-name kills. POSIX uses process groups, which are weaker against deliberate session detachment. Child environments exclude inherited provider credentials and application homes. Startup, functional and artifact validation will be qualified again against Bun after the exclusive R1 runtime lease is released. Native adapter integration will then reuse the frozen R1 financial structure and require new prompt/profile qualification with the same role graph.
