# Held-out maintenance workload

This synthetic offline workload upgrades an existing service rather than
building another empty CRUD scaffold. It asks for a durable storage migration,
several connected business workflows, concurrency/recovery behavior, scoped
authorization, a command line and a typed client. No real financial operation,
external account or company data is used.

Requirements and an exact 50-business/4-prerequisite inventory were registered
before the independent evaluator. The original evaluator was committed before
private-reference authoring; final peer coverage corrections came during that
authoring, before any runtime evaluation. The complete chronology is retained
in `INSTRUMENT_CORRECTIONS.md`. The separate private reference remains outside
this directory and every paid task workspace.

The working v1 seed legitimately passes some business checks. Qualification must
record its actual complete result, retain all failed checks and compare all54
checks against the private reference. A partial working baseline must never be
reported as an empty scaffold or forced to zero. Five damaged references must
fail their named assertions before runtime qualification can be claimed.

At source publication this task is **not runtime qualified**. Only six pure
Python static controls and six seed/private-reference module syntax checks have run. No model,
provider, Bun, browser, application server or paid benchmark execution is claimed.
An owner must release the shared runtime lease, qualify the actual Bun/node/TS
toolchain and native adapters, freeze all inputs and bind the unchanged budget
before any paid arm is admitted. Source files alone do not authorize spending.

The gate uses directly owned process trees and temporary data outside authored
sources. Windows children are placed in kill-on-close jobs before resuming.
Evaluation must leave authored files unchanged. The held-body test covers one
controlled revocation schedule, not all race orderings or production security.

python -B scripts/benchmarks/maintenance-holdout/evaluate.py --app <app> --out <new-output> --runtime <bun> --node <node> --typescript <tsc.js> --mode bun-qualification
