# Heavy application native-team comparison

`heavy_runner.py` is a separate, default-plan-only entry point. It does not
launch the old three maintenance-task loop. The first heavy experiment is one
Vector/Codex pair on the qualified Foundry scaffold, in that order. The task was
observed previously; this is a development replication, not a held-out result.
Any later pair requires inspecting this pair's evidence and a separate plan.

Both runtimes use Sol High, summary auto, verbosity low, 1,050,000 context and
32,000 output ceiling. The fixed seven native identities are:

```text
lead
  backend_coordinator
    backend_api
    backend_data
  frontend_worker
  qa_specialist
  team_judge
```

The coordinator integrates only after both leaves complete. QA starts after
the implementation roles complete. The judge reviews all five non-judge child
roles, including the nested leaves and QA, before the lead's final API/browser
verification. Same-identity follow-ups are permitted; replacements and other
edges are refused before inference. Only the lead and backend coordinator may
delegate. File ownership and read-only review responsibilities are prompt and
runtime policy, not an operating-system file-write fence.

The original four-role helpers remain the default. Optional profile arguments
select the closed heavy graph and funding profile; no mutable global profile
is switched. Vector uses Thorough to expose TaskTool and automatic judge off.
Codex preserves native code mode and six child slots. All actual worker,
specialist, judge, helper, retry and repair requests share the authoritative
meter. The witness serializes provider requests for both arms, so wall times
are not production team-throughput measurements.

The approved funding phase is `heavy-matched-teams-high-v1`, bound to its
separate allocation-plan SHA in `funding_profiles.py`. The $48 total and all
889 previous calls / $20.3038291 remain. Cumulative actor limits are
$24.73654725 Vector and $20.31968465 Codex, providing equal new additional
allowances of $13.84808545. Historical actors remain sealed. The old default
funding phase and $20 caps remain unchanged when this profile is not selected.
Every status, drain and reservation validates the raw heavy state. Each arm
requires at least $5.73 pre-arm reservation headroom, then actual per-request
reservations. No context, images or output ceiling is reduced to fit.

The heavy $13.84808545 threshold admits a formal repair only after the previous
invocation settles; it never stops an invocation mid-call. The hard meter caps,
300-request and two-hour execution bounds still apply. At most one same-lead
formal repair is allowed. A trusted audit boundary records that admission, and
the same QA/judge must recheck after it. Ordinary background-notification turns
are not treated as formal repairs. All charges and unknown closures remain.

The closed Foundry contract copies `instrument/BUILD_SPEC.md` to the scaffold as
`BUILD_SPEC.md`, preserving the original five-file starting state. Its unchanged
wrapper receives explicit Bun, Node, Chromium and Playwright paths and retains
32 API checks, 40 browser checks and four prerequisites: 76 total. Evaluator
timeout is 1500 seconds. Missing/not-run checks cannot establish a product pass.
The independent wrapper and its raw report are not supplied to coding agents.

Required plan inputs are `--vector-root`, `--common-runner-root`, `--task-dir`,
`--browser-driver-root`, `--bun`, `--node`, `--codex-bin`, `--chrome`,
`--playwright-module`, a new private `--out` and synthetic `--label`. Planning
freezes source, full task/instrument/browser manifests, role semantics, runtime
paths and executable/package fingerprints. It reads no controller credentials
or receipt ledger, even if missing private paths are supplied. `--write-plan`
can save the reviewed plan object. Only `--run --reviewed-plan FILE
--expected-plan-sha SHA --expected-source COMMIT` with explicit private
`--controller-config` and `--receipt-jsonl` can read the existing local controller
capability. The runner never loads the real provider key. CLIs receive only
owned aliases, not controller or funded batch capabilities.

Native descendant transcripts and owned process quiescence are required.
Unknown native item schemas, incomplete commands and opaque execution stay
manual review. Codex commands come from persisted native CommandExecution
events, including code-mode calls; JavaScript is never evaluated by the audit.
An incomplete arm blocks the other arm and is reported explicitly, not omitted
from a favorable denominator. The coordinator never automatically starts a new
pair or claims efficiency. Functional/native execution passes remain distinct
from a separate blinded 48-point review: no lower Vector score on a task and
no established critical regression may be averaged away.

`heavy_adapter_smoke.py` is a separate fake-only qualification entry point. It
uses the actual NativeAdapter commands/profile, ephemeral Python fake meter,
dummy capabilities, labelled local fixture API/page and unchanged real Foundry
scaffold. The real 76-check scaffold gate must remain negative twice. The
script exercises nested leaves, actual shell/common-browser actions, same-QA
and judge continuations, and a Vector background worker plus completion
notification. No provider/controller credential is loaded, no funded port is
used, and fake capability success is not app-quality evidence. Outputs and
native IDs/prompts remain private; publish only reviewed counts and hashes.
